最后核验：2026-08-13

本文描述当前系统的有效状态，不记录架构讨论过程。当前仓库尚无业务代码，因此没有可声明的运行时系统架构。

## 当前状态

- 业务模块：无。
- 运行时数据流和控制流：无。
- 硬件接口和软件接口：尚未定义。
- 产品外部依赖：尚未选择。
- 已验证硬件资源约束：无。

目录名不能证明具体芯片、开发板或 SDK。相关内容在获得证据前保持未决。

## 仓库治理结构

当前唯一已建立的是开发治理层：

| 组成 | 职责 | 边界 |
| --- | --- | --- |
| `AGENTS.md` | 自动加载的项目工作规则和阅读入口 | 不保存易变化的业务状态或历史流水账 |
| `docs/PROJECT_CONTEXT.md` | 当前产品目标、需求、非目标、约束和未知项 | 不描述代码模块实现 |
| `docs/ARCHITECTURE.md` | 当前有效系统结构、接口、流和资源边界 | 不记录候选方案讨论和历史版本 |
| `docs/decisions/` | 长期架构决策及其代价、状态和重评条件 | 不记录普通实现细节 |
| `docs/STATUS.md` | 当前唯一 Phase 入口和最近阶段索引 | 不复制完整阶段历史 |
| `docs/DELIVERY_WORKFLOW.md` | Phase、验收、升级、报告和 Git 流程 | 不替代具体 Phase 的验收标准 |
| `docs/phase-reports/` | 已完成 Phase 的结果和可复验证据 | 不复制 Git diff 或完整日志 |

上下文流为：

`AGENTS.md → 项目上下文/当前架构/有效 ADR → 当前 Phase → 相关代码与测试 → 验收证据 → 阶段报告与 Git 基线`

## 当前不可破坏的边界

- `PROJECT_CONTEXT` 管“为什么和需要什么”，`ARCHITECTURE` 管“系统现在是什么”，ADR 管“长期选择为何如此”，阶段报告管“某阶段实际发生了什么”；不得互相复制职责。
- 架构现状变化时更新本文；需要保留选择理由时创建或替代 ADR；不要在本文追加历史版本。
- 未经有效 ADR 和对应 Phase 授权，不得引入或替换核心框架、通信协议、数据模型、持久化方式、状态管理策略或硬件接口策略。
- 任何未来业务模块都必须有单一主要职责、明确接口和可独立验证的边界。
- 文档治理层不能成为业务运行时依赖。

## 首个业务 Phase 前必须补齐

在实现业务功能前，至少确认并写入：产品目标、目标硬件、SDK/构建方式、首个最小用例和可重复验收方法。随后在本文件中新增实际模块、职责、边界、数据流、控制流、接口、依赖和资源预算；需要长期取舍的选择同时建立 ADR。

## 维护触发条件

以下任一情况发生时必须在同一 Phase 更新本文：模块新增/删除或职责改变、主要数据流或控制流改变、外部接口改变、核心依赖改变、硬件边界改变、关键资源预算或禁止边界改变。
